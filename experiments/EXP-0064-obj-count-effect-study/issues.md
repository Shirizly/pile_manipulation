# EXP-0064 — issues found while porting (2026-10-03)

Status key: **fixed here** (a corrected run exists in this record) · **mitigated
in eval** (RUN-0006 controls for it at scoring time; the trained model still
carries it) · **open** (cannot be fixed from this repo, or needs a user
decision).

| # | issue | effect | status |
|---|---|---|---|
| I-1 | **Action read in a z-mirrored frame.** `GroupedParticleDataset` and `eval_grouped_capture.py` use the stored action `[x0, a1, x1, a3]` as particle `(x, z)`; the collector stores `(x, -z)` (invariant `flex-action-frame-neg-z`, same collector as DS-0019/20). Measured (RUN-0007, `results/frame_check.json`): cos(moved-particle displacement, push direction) 0.99 under z = -a1 vs ~0 literal on both DS-0021 and DS-0022; cos(true node displacement, the GNN's action input) 0.68 corrected vs **0.05 as run**. | MODEL-0011 was trained and scored with a nearly uninformative action channel. Its accuracy/capture numbers (and the per-group trend) describe that, not the GNN's ability. | **fixed here**: `train.action_z_sign` knob (default +1 = as run); RUN-0005 retrains with -1 and nothing else changed → MODEL-0012; RUN-0006 scores both. |
| I-2 | **Escaped particles in rows marked valid.** Any \|x\| or \|z\| > 10 (DS-0019's `escape_abs`). Train (DS-0021, 1500-row sample): 3.5 / 5.0 / 8.6 / 14.6 % by group; test (DS-0022): see `results/extended_summary.md` pool facts. The collector's explosion check misses them. | Contaminates training targets more for larger piles; the as-run eval kept them (huge squared errors and mean-distance outliers for any tracked escaped particle). | **mitigated in eval** (RUN-0006 reports clean-row numbers). Training NOT filtered (kept identical to isolate I-1) → **open**: a retrain with an escape filter. |
| I-3 | **Action encoding is not the baseline's.** The adapter uses `transforms.functional.build_action_delta` (Gaussian tube of sigma 1.2/24 around the push segment × the FULL push vector, also behind the start point). The source baseline `ParticleDataset` (`code/ported_reference/dataset_gnn_dyn_original.py`) encodes distance-to-push-end along the push × direction × hard length gate × soft width gate (half-width 0.8/24). | The study is not "the baseline GNN with only data loading swapped" — the action channel is different. Effect size unknown. | **open** (user decision: baseline fidelity was the stated goal; porting the original encoding is a few lines in the adapter + one retrain). |
| I-4 | One training window per state (frames 0-5 only). | Half of DS-0021's transitions (steps 5-9) are never used; 1800 windows for a 2000-state corpus. | open (design choice of the port; note only). |
| I-5 | As-run eval FPS was unseeded (`np.random.randint` start). | Exact as-run numbers are not reproducible; RUN-0006 reproduces them within ~0.01 with seeded FPS (3 reps). | **fixed here** (seeded reps). |
| I-6 | As-run capture: one uniformly random point goal per state; cost and truth computed on the <= 30 tracked nodes only. | Tiny goal breadth (METRICS.md: slateN is weak with one goal); truth on 30 nodes is a proxy for the pile. | **mitigated in eval**: 17 point goals, all-particle truth via nearest-node carry, plus the project's mask goals (random_quadrant / ring_O / T x 3 value functions). |

## What it is
One JSON per (scenario, pipeline): the FASTEST solved trajectory found so far (replaced only by a strictly faster one).
Scenario = EXP-0076 `results/scenarios.json` entry: n cubes (20 / 50), init (Sean spawn mode of a chain-start state from a
Sean TEST-split file -- never seen by the Sean-trained models), goal spec (disc / square at random position + size, or letter
O/T/S/X at stroke width w20 / w15 shifted at random; cube top area / goal area <= 0.6, goal inside |x|,|y| <= 54 mm).
Success = in-goal mass fraction of the soft scoring raster (`simple_mpc.adapters.occ_for_scoring`) >= 0.95.
Time = physical execution time (EXP-0070 `action_time`: lift + transit + descent + sweep, from HOME), planning time excluded.

## Record keys
`id, n, init, kind, goal (spec), solved, pushes, time_s, push_times, final_mass, masses (T+1), values (lyap - mass, T+1),
actions (T x [sx, sy, ex, ey] world m; blade perpendicular to the push), states (T+1 x n x 3), quats (T+1 x n x 4, w x y z),
pred_cost (model's predicted cost of each executed push), plan_s, n_sims, wall_s, method {pipeline, B, k, model, H, gd, ...}`.
Goal masks are regenerated by `tasks.goal_mask(goal)` (64 x 64, mask[x_px, y_px]).
Every executed push is legal (touchdown-legalised before simulation, `wide_planner.make_legal_scorer` constants).
Physics: TRAINING_PHYSICS (friction 0.7 / box 0.5, density 450, settle 3000), real settle / clearance budgets.

## How a trajectory was simulated
Each push is simulated from the recorded previous state put into an env with `set_particle_state` (velocities zeroed; states
are settled), then `execute_action` + `update_material_state`. Search pipelines branch from restored states, so a recorded
trajectory is a chain of true simulator transitions; replaying the action list open loop in one continuous env can differ
slightly (Genesis call-history dependence, C-033) -- replay checks are recorded in EXP-0076 LOG.md.
